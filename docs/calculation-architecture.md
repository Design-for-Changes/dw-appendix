# 計算コアと関数対応表

## 利用する入口

公開入口は `computeSeries({ household, scenario, tables, sweep })` であり、同じ世帯の給与系列を計算する。内部の `computePoint(ctx, x)` が給与1点を計算する。`x` と `sweep` の min/max/step は給与収入（万円/年）。金額の返却キーは原則として `Yen` が円、`Wan` が万円を示す。ただし、教育需要額の一部は円/月であり、各関数のコメントと返却キーを確認する。

表示用JSONは `npm run generate:appendix` で生成する。現行制度系列の生成後、`computeOptimalModel(series, household)` によって探索的な調整モデルを計算する。ブラウザの表示処理に計算式を重ねて実装せず、生成済みの同じ系列を使う。

## モジュールの責務

| モジュール | 内容 |
| --- | --- |
| `numeric.js` | 年度キーの正規化、数値化、丸め、控除行の整形 |
| `household.js` | 世帯・児童属性の正規化、入力表の準備、給与所得・基礎控除の表適用、各世帯員の計算行 |
| `deductions.js` | 配偶者・扶養・障害者控除等の集計と課税所得 |
| `taxes.js` / `taxDescriptions.js` | 所得税・住民税の算定と説明 |
| `socialInsurance.js` | 年金・医療・介護・雇用保険料 |
| `allowances.js` | 特別児童扶養手当等の所得判定用補助・現金給付 |
| `medicalAid.js` | M01の所得判定・代表額の取扱い |
| `educationAid.js` | N04の生活保護基準による需要額・支弁区分・補助額 |
| `computePoint.js` | 上記の結果と通所負担等を組み合わせ、手取額・可処分所得を返す |
| `optimalModel.js` | 追加需要、支給額G、負担上限U、精算後の可処分所得 |
| `tableUtils.js` | 整数の範囲制限、入力表の最近傍行の取得と補間 |
| `cliffCauseAnalysis.js` | 下落要因の分解（表示用生成とCLIレポート等）。表示用Q/R点は生成スクリプトで探索 |

`computePoint.js` から従来の13個のexportを維持し、利用側のimportを壊さない構成としている。モジュール分割は計算式・定数・丸め・演算順序を変更しない範囲で行った。

## 関数一覧の再生成

```sh
npm run generate:functions
npm run verify:functions
```

構文木から名前付き関数とクラスを列挙し、JSDocの説明・引数・返却値を対応づける。対象は `src/calc/*.js` と `scripts/generate-appendix-data.mjs`。無名コールバック、Reactの表示処理、検証スクリプトは含めない。説明のない関数は生成エラーとし、説明を推測で補わない。ソース位置を含むJSONを独立したWeb Appendix F「関数資料」の表A3へ表示する。

対応表の関数名からページ内の説明へ移動し、説明から対応する処理へ戻れる。ソースへの外部リンクは説明行にまとめる。リンクのキーにはファイルと階層名の完全IDを用い、同名関数を区別する。補助関数の字句上の内包元も辿れるが、実行時の呼出関係とは扱わない。

## 検証の役割

```sh
npm run verify
CI=true npm test -- --watch=false --runInBand
npm run build
```

検証は、原典マニフェストとの対応、独立した検算例、既存の期待値、生成データと計算コアの一致、関数一覧とソースの一致を分けて行う。さらに `verify:contract` では、分割前に記録した21条件・27,321給与点の全返却値と、160個の生成JSONのハッシュを比較する。出力一致はリファクタリングによる数値変化を検出する検証であり、元の制度式や年度設定が妥当であることの証明ではない。

## 数値を解釈する際の範囲

- 現在のM01は、助成の実績平均を用いた従来設定を保持している。他の子ども医療費助成への切替え後の最終負担を計算するものではない。
- 通所負担の10,406円は、東京都の2024年6月の放課後等デイサービス・一般2区分の児童単位の平均であり、複数児童がいる世帯全体の平均ではない。
- 調整モデルの常時介護分は月額16,100円を追加需要の代理値とする。医療的ケアの追加需要は独立の項として実装していない。Eplanは系列内の最大費用等から置く世帯定数、Eextraは0である。
- 公開画面の下落点一覧は税制に伴う下落も含みうる。論文で制度横断的影響の検討対象を選んだ表とは、抽出条件を区別する。
- 年度、所得限度額の境界、住民税非課税の特例、世帯条件拡張時の加算表等は、出力一致とは別に原典へ照合する必要がある。数値修正を行うときは、変更理由と期待値を別途記録し、既存出力へ合わせるためだけに期待値を更新しない。
