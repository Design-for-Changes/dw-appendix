# 回帰検証の方法

## 目的

計算式、定数、端数処理または表示用データ生成を変更したときに、制度上の変化点が意図せず
移動していないことを確認する。

## 検証単位

`fixtures/cases.json` には、モデル世帯ごとに給与収入を1万円刻みで掃引した際の期待値を記録する。
期待値は次のいずれかである。

- 下向きの変化点の給与収入
- 変化点における可処分所得の落差
- 下向きの変化点が存在しないこと

位置を厳密に照合する項目は `positionExact: true` とし、代表値または暫定値を含む項目は
個別の許容差を設定する。

## 制御ケース

V系列は、世帯条件を一項目ずつ変え、各制度の判定要素を分離して検証する。

- V0：現金給付・費用軽減制度を持たない基礎系列の単調性
- V1〜V3：障害区分と扶養人数による特別児童扶養手当の所得制限
- V4：障害児福祉手当の扶養義務者所得制限
- V5：16歳以上の通常扶養控除が住民税所得割判定に与える影響

提示ケースP1〜P3は、複数制度を同時に適用した最終表示系列を検証する。

## 自動照合

`npm run verify` は計算コアから各ケースの系列を生成し、隣接する給与点の可処分所得差から
変化点を検出する。検出結果をfixtureの給与位置・落差と照合し、未定義の下向き変化点も検出する。

`npm run verify:appendix-data` は、計算コアから生成した表示用JSONについて次を確認する。

1. P1〜P3が200万円から1400万円まで1万円刻みで連続していること。
2. fixtureに記録した変化点が表示系列にも存在すること。
3. 軽量な曲線データと詳細内訳の可処分所得が全給与点で一致すること。
4. ブラウザ用コードが計算コアを直接実行せず、生成済みデータだけを読むこと。

原典資料との対応は `npm run verify:sources`、主要算式の独立照合は
`npm run verify:oracle` と `npm run verify:social` で確認する。
