# 回帰検証の方法

## 目的

計算式、定数、端数処理または表示用データ生成を変更したときに、制度上の変化点が意図せず
移動していないことを確認する。

## 検証単位

`fixtures/cases.json` は旧期待値の履歴として保持する。制度式是正後の表示用期待値は `fixtures/display-corrections-20261115.json` に別記録する。モデル世帯ごとに給与収入を1万円刻みで掃引した際の期待値を記録する。
期待値は次のいずれかである。

- 下向きの変化点の給与収入
- 変化点における可処分所得の落差
- 下向きの変化点が存在しないこと

位置を厳密に照合する項目は `positionExact: true` とし、代表値または暫定値を含む項目は
個別の許容差を設定する。

## 制御ケース

V系列は、世帯条件を一項目ずつ変え、各制度の判定要素を分離して検証する。

- V0：現金給付・費用軽減制度を持たない基礎系列の単調性
- V1〜V3：障害区分と扶養人数による特別児童扶養手当の所得制限
- V4：障害児福祉手当の扶養義務者所得制限
- V5：16歳以上の通常扶養控除が住民税所得割判定に与える影響

提示ケースP1〜P3は、複数制度を同時に適用した最終表示系列を検証する。

## 自動照合

`npm run verify` は、原典対応、独立oracle、表示系列、個別制度資料、条件定義、関数資料、全返却値の回帰契約を照合する。原典の一致点±1円などの単体テストは `CI=true npm test -- --watch=false --runInBand` で別に実行する。

旧崖期待値との照合は `npm run verify:legacy-cliffs` として保存する。現在の制度式是正後の結果は旧期待値と一致しないため、これを通常の合格条件には使わない。原因と主要境界の旧新対照は[更新記録](calculation-update-20261115.md)に示す。

`npm run verify:appendix-data` は、計算コアから生成した表示用JSONについて次を確認する。

1. P1〜P3が200万円から1500万円まで1万円刻みで連続していること。
2. fixtureに記録した変化点が表示系列にも存在すること。
3. 軽量な曲線データと詳細内訳の可処分所得が全給与点で一致すること。
4. ブラウザ用コードが計算コアを直接実行せず、生成済みデータだけを読むこと。

原典資料との対応は `npm run verify:sources`、主要算式の独立照合は
`npm run verify:oracle` と `npm run verify:social` で確認する。

## 回帰契約と旧版の保存

`npm run verify:contract` は `fixtures/calculation-contract-20261115.json` と照合する。21ケース・27,321給与点の全計算結果、および表示用160ファイルの正規化JSONをSHA-256で比較する。原典例・境界テストと原因別の旧新比較を行った後の回帰値であり、制度式の全範囲の正しさを保証するものではない。

分割前の契約 `fixtures/refactor-contract.json` は上書きせず保存した。`npm run verify:legacy-contract` は現在の計算コアを旧契約へ照合する差分診断用であり、制度式是正後は不一致となる。旧版との同値検証と、意図した数値修正後の回帰検証を混同しない。

`npm run verify:functions` は、JSDocから生成した関数一覧の件数・説明・ソース行・内容ハッシュを照合する。
